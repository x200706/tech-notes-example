    Docker 踩坑筆記：從 Dockerfile 到上版

    把專案容器化時踩過的坑，整理成一篇。範例都改成現在的寫法，但每個專案的結構不同，直接貼上前還是要依情況調整。

    2024-04-11DockerComposeNginx

    01先畫架構，再寫檔案

    動手寫 Dockerfile 之前，先把 compose 的結構想清楚：有哪些服務、彼此怎麼連、哪些資料要保留。這樣才知道哪些服務能直接用官方映像，哪些需要自己的 Dockerfile。畫一張圖是最快的方法。

    02Dockerfile

    • 依賴和程式碼分開複製。Docker 是一層一層快取的，某一層的內容變了，後面每一層都要重做。先複製 pom.xml 或 package.json 裝好依賴，再複製程式碼，平常只改程式時就不用重裝依賴。
    • WORKDIR 不用每次重指。它對後面所有指令都有效。真正不會保留的是 RUN cd，每個 RUN 都是新的 shell，所以才常看到大家用 && 把指令串在同一行。
    • build 壞了又知道原因，就直接刪掉重 build。一直加 RUN 去補救沒有效率。要確定真的從頭來，加 --no-cache，不然可能還在用舊的快取層。
    • 容器內中文亂碼，補上 locale。很多基底映像沒有設定語系，加一行 ENV LANG=C.UTF-8。網頁輸出通常不受影響，但進容器看 log 或改檔案時會很痛苦。
    • 映像沒有 vim 很正常。需要就在 Dockerfile 裡裝，但正式環境的映像越小越好。alpine 版本小很多，不過它用 musl 而不是 glibc，少數套件會出問題。

    03Docker Compose

    • 不用再寫 version。新版 Compose 會直接忽略它，舊教學裡的 version: '3' 可以拿掉。
    • depends_on 只管啟動順序。它不保證 DB 已經可以連線，AP 還是可能搶先啟動然後報錯。要搭配 healthcheck 和 condition: service_healthy。
    • 除錯時先關掉自動重啟。restart: unless-stopped 適合大部分服務，但程式一啟動就掛時，容器會一直重啟，很難看到錯誤訊息。在容器裡跑 Node 的話，要用 pm2-runtime 而不是 pm2，否則程序跑到背景，容器會以為主程式結束了。
    • build 階段連不到其他服務。Compose 的網路只在容器執行時存在，所以 build 時就要連資料庫的步驟（例如安裝套件後自動跑的初始化腳本）會出現 getaddrinfo failed。這類步驟要移到容器啟動時執行。

    04掛載的坑

    • 掛進去的是同一份檔案。bind mount 在容器裡改，本機的檔案也會跟著變，反過來也一樣，不用重啟容器。但 Nginx 這類只在啟動時讀設定的服務，改完要 reload 才會生效。
    • 依賴目錄會被蓋掉。把整個專案目錄掛進去時，宿主機上沒有 node_modules（Java 的 target、PHP 的 vendor 也一樣），掛上去會把映像裡裝好的依賴蓋成空的。替依賴目錄另外掛一個卷就能保留。
    • 宿主機路徑不存在，Docker 會幫你建一個空目錄。log 路徑寫錯，就多一個奇怪的資料夾；設定檔本機還沒寫就掛進去，容器裡會變成一個空目錄，服務直接起不來。掛之前先確認本機的檔案在。
    • 單一檔案掛載，存檔後容器可能看不到。單檔掛載綁的是那個檔案本身，有些編輯器存檔是先寫新檔再取代，容器裡看到的還是舊內容。掛整個目錄就沒有這個問題。另外，改了 compose 的 volumes 設定要重建容器，執行 docker compose up -d 會自動處理。
    • 權限跟著宿主機。掛進去的檔案權限以宿主機為準，在 Dockerfile 裡 chown 對執行時才掛上的路徑沒有作用。應用要寫入的目錄（log、暫存、上傳）要先在宿主機建好並給寫入權限。我遇過寄信套件找不到暫存目錄，最後是在掛載的 storage 底下建一個 tmp 並開放寫入才解決。
    • Windows 的換行會帶進容器。從 Windows 掛進去的腳本常在行尾多出 ^M（CRLF），shell 腳本會直接執行失敗。在專案加一個 .gitattributes 統一用 LF 最省事。
    • log 不掛，容器一刪就沒了。官方建議把 log 輸出到 stdout，用 docker compose logs 看；需要保留成檔案就掛出來。官方 Nginx 映像的 log 檔看起來是空的，就是因為它已經把 log 導到 stdout 了。

    05網路

    • 服務名稱就是主機名。在同一個 Compose 網路裡，Nginx 寫 proxy_pass http://api:8080 就連得到，不用查 IP。
    • 透過 Docker 網路轉送時，Host 會變。API 收到的 Host 會變成「服務名稱:port」，程式裡有依網域判斷的邏輯就會失準。轉送時把原本的 Host 帶過去；對外的 API 最好綁自己的網域，讓前端和瀏覽器都從同一個網域進來。

    06排程

    容器裡通常沒有 cron。最簡單的做法是讓宿主機的 crontab 去觸發容器裡的指令。注意不要加 -it：cron 執行時沒有終端機，加了會直接失敗。有人覺得這樣「不夠 Docker」，另一個做法是開一個專門跑排程的容器。

    07上版

    • docker restart 不會換新映像。它只是把同一個容器重開一次。「先 build 再 restart」看起來有更新，其實跑的還是舊程式，要用上面的 up -d --build 重建容器。
    • 快取讓上版變快。依賴和程式碼分開複製之後，大部分上版只會重做最後幾層。遇到行為怪異、懷疑是快取的問題時，再用 --no-cache。
    • 重新 clone 之後服務異常，先清快取。舊的框架快取檔還留在容器或掛載目錄裡，跟新程式對不上。清掉快取目錄通常就好了。
    • 這樣上版會有幾秒中斷。要做到不中斷，下一步是滾動更新：開多個實例，一台一台輪流換。

    08Windows 的 Docker Desktop

    • 家用版一直轉圈，先別照網路教學下 -SwitchDaemon。它會切換到 Windows Container，但家用版不支援，切回去時常常直接報錯，最後只能重裝。
    • 多半只是權限不足。關掉 Docker Desktop，對圖示按右鍵用系統管理員執行就好。
    • Compose 專案要從命令列啟動。啟動之後在 GUI 裡看得到。

    Linux 小抄

    維運主機時最常查的指令。前面加 sudo 的是需要 root 權限的指令，已經是 root 或設定好 sudoer 就可以省略。

    2024-03-27LinuxUbuntuShell

    01系統與服務

    指令用途
    cat /etc/os-release看這台是哪個發行版、哪個版本
    sudo systemctl restart nginx管理系統服務，可換成 start、stop、status
    journalctl -u nginx -f追某個服務的日誌
    crontab -e / crontab -l編輯／列出排程；加 sudo 改的是 root 的排程
    grep CRON /var/log/syslog查排程有沒有執行（Ubuntu）
    free -h記憶體用量
    df -h硬碟用量
    du -sh *目前目錄下每個項目各佔多少空間；加 -a 會列出所有檔案
    timedatectl看目前時間與時區
    sudo timedatectl set-timezone Asia/Taipei改時區

    排程編輯器　第一次執行 crontab -e 會問要用哪個編輯器，選錯了可以用 select-editor 重選，或直接 EDITOR=vim crontab -e。

    02檔案、輸出與搜尋

    指令用途
    指令 > out.txt把輸出寫進檔案，檔案已存在會被覆蓋
    指令 >> out.txt同上，但接在檔案後面
    指令 > out.txt 2>&1連錯誤訊息一起寫進去
    tail -f /var/log/syslog即時看 log 新增的內容；大部分 log 都在 /var/log
    find / -name "*haha*" -type f從根目錄找檔名包含 haha 的檔案
    grep -rn "keyword" ./src在目錄裡遞迴搜尋內文，-n 顯示行號
    tree -L 2用樹狀圖看目錄結構（要另外安裝）

    03網路

    指令用途
    ss -tulpn看哪些 port 正在監聽、是哪個程式
    ss -tulpn | grep :8080看 8080 被誰佔用
    netstat -tulpn | grep LISTEN舊主機的寫法，新系統可能沒裝 netstat
    curl -I https://example.com只看回應的 header
    curl -v https://example.com看完整的請求與回應過程，除錯 SSL、轉址時好用

    04Vim 救命鍵

    按鍵用途
    gg / G跳到檔案開頭／結尾
    /keyword往下搜尋，n 跳到下一個
    :wq存檔並離開
    :q!不存檔直接離開

    05裝套件之前

    網路教學常常附 apt install -y，-y 會自動同意所有變更。在跑了很久的舊主機上，它可能順手升級一堆相依套件。先不加 -y，看清楚要裝、要升級哪些東西再決定。

    SQL 小抄

    常用語法和自己犯過的錯，以 MySQL 為主。語法本身不難，難的是資料量變大之後，有些寫法會變成效能瓶頸，所以每段都順便記下對索引的影響。

    2024-03-14MySQLSQL索引

    01NULL 與引號

    • 判斷 NULL 要用 IS NULL。= NULL 永遠不成立。想撈「不等於某值」的資料時，NULL 也不會被撈出來，要另外用 OR 欄位 IS NULL 補上。
    • 表名、欄位名不要加單引號。單引號是字串，WHERE 'created_at' >= ... 比的是字串本身，不會報錯，但結果完全不對。要括起來用反引號 `created_at`。我一開始就是這樣查了半天，最後才發現是引號。
    • MySQL 的雙引號預設也是字串。網路上寫成 "欄位名" 的範例來自其他資料庫，在 MySQL 不要照抄。
    • 不等於寫 <> 最通用。MySQL 也接受 !=，但 <> 是標準寫法，換資料庫也能用。

    02日期查詢

    • DATETIME 用「大於等於起日、小於隔天」。BETWEEN '2024-03-01' AND '2024-03-31' 只算到 31 號的 00:00:00，那天其他時間的資料都會漏掉。
    • 函數套在常數那邊，不要套在欄位上。WHERE DATE(created_at) = ... 會讓欄位上的索引失效，資料一多就變成全表掃描。
    • Unix 時間戳要轉換。欄位存的是整數，用 UNIX_TIMESTAMP() 把比較的日期轉成整數，欄位一樣用得到索引。
    • 型態都對了還報錯，可能是資料本身有問題。例如混進 0000-00-00 這類無效日期，新版 MySQL 的嚴格模式會拒絕。

    03型態與條件

    • 數字存成字串時，比大小要先轉型。直接比字串，'9' > '12000' 會成立。用 CAST 轉成數字比較，但這樣一樣用不到索引，長期還是應該把欄位改成數值型態。
    • 多個值用 IN，條件可以直接運算。
    • CASE WHEN 用在依條件回傳不同的值。

    04GROUP BY

    SELECT 裡的欄位要嘛出現在 GROUP BY 裡，要嘛被聚合函數包起來。DATETIME 只想按天統計時，SELECT 和 GROUP BY 要用同一個運算式。

    05排除資料與子查詢

    • 排除「有關聯資料」的列，用 NOT EXISTS。子查詢裡的 SELECT 1 只是佔位，EXISTS 只在乎有沒有資料，不在乎選了什麼欄位。
    • 小心 NOT IN 遇到 NULL。子查詢結果只要有一個 NULL，NOT IN 就會一筆都查不到，NOT EXISTS 沒有這個問題。

    06UNION 與排序分頁

    • 欄位名稱不同但意義相同，用別名對齊再 UNION ALL。UNION 會去重複，比較慢；確定不會重複就用 UNION ALL。
    • ORDER BY 在前，LIMIT 在後。排序欄位有重複值時，分頁可能出現重複或漏掉的資料，要再加一個唯一欄位當第二排序條件。

    07索引

    • 常出現在 WHERE、JOIN、ORDER BY 的欄位，考慮加索引。
    • 索引有代價。寫入和更新會變慢，也會佔空間，不是越多越好。
    • 複合索引看「最左前綴」。等值條件的欄位放前面，範圍條件的放後面，跟 WHERE 裡寫的順序無關。
    • 對欄位套函數或轉型，索引就用不到。前面日期和字串轉數字的例子都是這個原因。
    • 不確定就用 EXPLAIN。看 key 有沒有用到預期的索引、rows 掃了多少列。

    08備份與還原

    InnoDB 加上 --single-transaction，可以在不鎖表的情況下拿到一致的備份。帳號權限不在一般的資料庫備份裡，要另外用 SHOW GRANTS 匯出。
